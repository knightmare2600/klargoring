Projekt Lods — Automated Debian Trixie + Proxmox VE ZFS Installer
Project Objective

Build an automated bare-metal installer which replaces the Proxmox ISO installer workflow.

The goal is to create a custom installer which:

boots via PXE/iPXE
consumes a Proxmox-compatible TOML answer file
automatically provisions Debian GNU/Linux Trixie
creates a ZFS root filesystem
installs Proxmox VE
configures first boot automation
produces a fully operational Proxmox node without manual intervention

The design philosophy is:

Do not use Debian Installer partman.

Instead, replicate the architecture used by the Proxmox installer:

prepare disks manually
create storage manually
bootstrap Debian using debootstrap
configure the target system
install Proxmox packages
install bootloader
reboot into the finished system

Input Format

The installer must consume TOML.

Existing format:

[global]
keyboard = "en-gb"
country = "gb"
fqdn = "pve-install.jukebox.internal"
mailto = "root@jukebox.internal"
timezone = "Europe/London"

root-password-hashed = "$6$..."

root-ssh-keys = [
"ssh-rsa AAAA..."
]


[network]
source = "from-dhcp"


[disk-setup]
filesystem = "zfs"
zfs.raid = "raid1"
disk-list = ["sda", "sdb"]


[first-boot]
source = "from-url"
ordering = "fully-up"
url = "http://192.168.139.50/proxmox/first-boot.sh"

The installer should not convert this.

It should parse this directly.

Implementation Language

Use:

Python 3

Reasons:

built-in TOML parser (tomllib)
excellent subprocess handling
easier testing
easier future expansion

Avoid implementing this in Bash.

Bash may be used internally for small system operations only.

Definition of Done

The project is successful when:

A machine PXE boots.

It downloads:

answer.toml

The installer:

wipes two disks.
creates ZFS mirror.
installs Debian Trixie.
installs Proxmox VE.
configures SSH.
enables first boot automation.
reboots.

After reboot:

https://hostname:8006

shows a working Proxmox VE installation.

Development Order

Implement in this order:

TOML parser.
Logging framework.
Disk detection.
Partition creation.
ZFS creation.
debootstrap.
chroot configuration.
GRUB installation.
Proxmox installation.
First boot service.
QEMU integration tests.

Do not attempt the entire installer in one step.

Build each stage independently and test before moving on.

This project is intended to become a reusable bare-metal hypervisor provisioning system, not a one-off script. The existing Proxmox answer TOML format should remain the API contract
